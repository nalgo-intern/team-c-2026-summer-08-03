# レシピ提案アプリ

手元にある食材から、作れる料理を提案する Web アプリです。
食材はテキストで入力するほか、写真をアップロードして自動認識させることもできます。

一人暮らしや家庭では「食材を使いきれずに捨ててしまう」「あるもので作れる料理が思いつかない」
といったことが起こります。このアプリは献立を考える時間を短縮し、食品ロスの削減を支援します。

グループC ／ 木村 大暉・黒田 燎汰・新井 柚香

---

## 主な機能

| 機能 | 内容 |
|---|---|
| 食材のテキスト入力 | カンマ区切りで複数入力。「トマ」と打つと「トマト」を候補表示。表記ゆれ（玉葱・たまねぎ）も正規化 |
| 食材画像の認識 | 画像をアップロードすると CLIP が食材を推定。上位3候補から選んで登録 |
| 選択中の食材の管理 | テキスト・画像どちらの経路も1か所に集約。個別に削除可能 |
| レシピ推薦 | 合致率と消費率でレシピを並べ替え、上位5件を表示 |
| 不足食材の提示 | そのレシピを作るのに足りない食材を明示 |
| レシピ詳細 | 料理画像・材料と分量・調理手順・所要時間・人数を表示 |
| 外部サイト連携 | クックパッド／クラシル／デリッシュキッチンへの検索リンク |

## 実行

```bash
streamlit run app.py
```

ブラウザで `http://localhost:8501` が開きます。

**初回の画像アップロードだけ数分かかります。** CLIP のモデル（約600MB）がダウンロードされるためです。
2回目以降は `~/.cache/huggingface/` から読まれるので数秒で終わります。

### 画像認識の評価

```bash
python scripts/evaluate.py
```

`data/eval_images/` の画像を一括で認識し、Top-1 / Top-3 / 食材ごとの正解率と、
誤認識した画像の一覧を出力します。

## アルゴリズム

### 食材画像の認識

**CLIP（ViT-B/32）によるゼロショット画像分類**を使っています。食材画像による学習は行いません。

CLIP は「画像」と「説明文」を同じ空間のベクトルに変換できるモデルです。
候補となる食材101件を `a photo of onion` のような英文にしてベクトル化しておき、
入力画像のベクトルと最も近いものを選びます。

学習データも GPU も不要で、`ingredients.csv` に食材を1行足せばそのまま認識対象が増えます。

### レシピの推薦

2つの指標の**調和平均**でレシピを並べ替えます。

```text
合致率 ＝ 共通する食材の数 ÷ レシピの主材料の数     … このレシピを作れるか
消費率 ＝ 共通する食材の数 ÷ 手元の主食材の数       … 手元の食材を使い切れるか

並び順 ＝ 2 × 合致率 × 消費率 ÷ (合致率 + 消費率)
```

分子は同じで、分母が「レシピ側」か「手元側」かだけが違います。
調和平均はどちらか一方が低いと全体が下がるため、**作れて、かつ多くの食材を使う**料理が上位に来ます。

同点の場合は TF-IDF によるコサイン類似度で決着をつけます。
150件のレシピ中で登場回数が少ない食材ほど重く数えるので、
「鶏もも肉を持っているなら、卵料理より鶏もも肉が主役の料理を上に」という並びになります。

調味料は常備されている前提とし、合致率・消費率の計算から除外しています。
合致率が 50% 未満のレシピは表示しません。

## 評価結果

### 食材画像の認識（50枚 / 10種類）

| 指標 | 目標 | 結果 |
|---|---|---|
| Top-1 正解率 | 80% 以上 | **84.0%** |
| Top-3 正解率 | 95% 以上 | **100%** |
| 食材ごとの正解率 | 60% 以上 | **最低 60%** |

上位3候補をユーザーに提示して選ばせる仕様のため、**Top-3 を主指標**としています。

食材ごとの内訳と、精度改善の経緯（豆腐の正解率を 40% → 100% にした話）は
[docs/開発メモ.md](docs/開発メモ.md) を参照してください。

### レシピ推薦

正解が一意に定まらないため、正解率ではなく「仕様どおりに算出されるか」をテストケースで検証しています。
全食材が揃っている場合・一部不足・調味料のみ不足・未登録食材・表記ゆれ・閾値未満の6項目すべて期待どおりです。

## 既知の制限

- **食材でない画像を弾けません。** 人物や風景をアップロードしても、何らかの食材候補が表示されます。判定方式の目処は立っていますが、閾値を決めるための評価画像が揃わず未実装です
- **食材の粒度が細かすぎる箇所があります。** 豆腐と高野豆腐、トマトとミニトマト、鶏肉の部位などは写真での判別が難しく、誤認識の主因になっています
- **評価データが1食材5枚しかありません。** 画像1枚の当たり外れが食材ごとの正解率を20ポイント動かすため、細かい優劣の判断には使えません

詳細と対応の方針は [docs/開発メモ.md](docs/開発メモ.md) の6章にまとめています。
